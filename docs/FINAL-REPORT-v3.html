Research Project · Concept Proposal

Domain-Agnostic
Hallucination Verification
Framework

A pluggable verification engine for evidence-grounded answers across Health, Legal, Research, News, Enterprise, and AI agents.

1. Executive Summary

1.1 The Problem

AI systems hallucinate. A factual error in a chatbot is recoverable; in a medical search engine, a legal tool citing a non-existent precedent, or a financial assistant, it is not. The central question is no longer "can the model produce a fluent response?" but "can we trust every factual statement in the response?"

1.2 The Gap

A domain-independent verification engine is missing. The landscape:

  • RAG-shaped tools (RAGAS, DeepEval, TruLens, Patronus) — one reference type, single-turn, no multi-evidence
  • Observability-shaped tools (Phoenix, LangSmith) — traces but no verification
  • Model-eval-shaped tools (OpenAI Evals, Promptfoo) — test models, not answers
  • Specialty tools (Galileo, Cleanlab) — small evaluators, closed weights, no agent eval

None accepts a heterogeneous bundle of evidence (PDFs, web, APIs, databases) and returns per-claim verdicts with confidence and source attribution.

1.3 The Solution — HVE

The Hallucination Verification Engine (HVE) takes three inputs — question, answer, references — and returns a Verification Report. It composes three patterns orthogonally:

  • Layered — 5-layer judge stack (lexical → embedding → NLI → LLM → jury) with short-circuit on confident verdicts
  • Graph — bipartite claim-evidence graph; verdicts are edges; conflicts are explicit
  • Plugin — six plug-in types with formal interface contracts

1.4 Expected Impact

  • 70–85% factual reliability on organic benchmarks across ≥5 domains
  • Auditability: every verdict traceable to the evidence that produced it
  • Domain independence: zero per-domain configuration
  • Cost viability: sub-$0.05 per typical verification at production scale
  • First-class conflict detection, bias correction, calibration — properties no existing framework provides

2. Why This Matters & Current Landscape

2.1 The 3 Research Gaps

Why HVE matters
Gap 1 — Heterogeneous evidence. Existing systems assume one reference type. Production has many (PDFs, web, APIs, DBs).
Gap 2 — Multi-reference aggregation. When references disagree, what is the verdict? No principled aggregation exists.
Gap 3 — Domain transferability. A Wikipedia-trained detector (FActScore) does not transfer to medical or legal. A domain-independent engine is needed.

3. The Architecture

3.1 The Composition

HVE is a Hybrid (Layered + Graph + Plugin) architecture. Three sub-architectures are composed orthogonally, not stacked:

  • Layered — cost-effective judging: lexical → embedding → NLI → LLM → jury, with short-circuit
  • Graph — multi-evidence reasoning: claims and evidence are nodes; verdicts are edges; conflicts are explicit
  • Plugin — extensibility: six plug-in types with formal contracts

Each addresses a concern the others cannot. Layered without Graph cannot represent multi-evidence. Graph without Layered pays full judge cost. Plugin without the others has no structure to plug into.

6. Concerns to Address

Open research concerns (above the line) and production risks (below the line), listed as pointers for discussion.

Research Concerns

  • Upper bound of accuracy — what is achievable with perfect retrieval, NLI, and LLM?
  • Optimal layer ordering — is lexical → embedding → NLI → LLM → jury optimal under all conditions?
  • End-to-end calibration — can joint training outperform post-hoc temperature / Platt / isotonic scaling?
  • LLM version drift — how is accuracy affected when pinned judge models upgrade?
  • Active learning — can selectively annotating the most uncertain verdicts improve the engine?

Production Risks

  • Calibration drift — distribution shift degrades the calibrator over time
  • LLM version drift — pinned judge versions become deprecated; reproducibility breaks
  • Retrieval failure cascade — if the retriever misses, the verifier has nothing to verify
  • Adversarial references — poisoned evidence could mislead the engine
  • Conceptual complexity — the Hybrid composition is harder to explain than a single pattern
